# Task 3.2 — live run view: the diagram plays the run, with an event feed

> Roadmap 3.2, the headline feature. Needs 3.1c (`feed` in `RunStateContext`).

## Goal
When a run arrives, the topology plays it: node bars follow the ticks, the
struck node flashes when the incident begins and shows its lost slots,
pulses run along the edges in proportion to their traffic, and a feed beside
the diagram prints the engine's lines as the clock reaches them.

## Measured first
- **Ticks arrive faster than they can be watched** (2026-11-15): 60 ticks of
  a 120 s run reach the browser within 0.3 s. "Live" is therefore a playback
  clock over the ticks held, capped at the newest tick received. On a run
  big enough to take real time the clock catches that edge and waits. One
  model, both cases. `web/tests/playback.test.ts` pins it.
- **Playback is cheap if only the frame redraws the diagram.** The diagram
  changes once per tick: 2.5 times a second on the demo (60 s, 2 s ticks, 5×),
  5 times a second on the examples (120 s at 10×). A full diagram render was
  measured at 0.4 ms at demo size (2026-10-09). The clock itself moves 60
  times a second, so it must not live in the page.

## Design (decided)

### The clock — `lib/playback.ts`
`Playback = {position, playing, speed}`; `position` is simulated seconds.
`PLAYBACK_SPEEDS = [1, 2, 5, 10, 20]`; `defaultSpeed(duration)` is the
slowest that plays the run within `TARGET_PLAY_SECONDS = 12`.
`advance(p, elapsedMs, edge, complete)` moves the clock, never past `edge`
(the newest tick's time, `liveEdge(ticks)`); at the edge of a finished run
it stops, at the edge of a run still arriving it waits. **When nothing
moves it returns the same object**, so a `setState(advance(...))` in the
frame loop re-renders nothing while paused or waiting. `seek`, `togglePlay`
(replays a finished run from 0), `setSpeed`, `atLiveEdge`, `frameIndex`.

### The frame — `lib/liveView.ts`
`liveFrame(nodes, ticks, chaos, position, interval)` → `{index, time, wholePath, edgeRates, nodes}`
for the newest tick at or before `position` (`null` before the first).
Per node: `utilization`, `queue`, `capacity` (live), `configured`, `inUse`,
`tone` (`liveTone`: crit ≥ 0.9, warn ≥ 0.75, the feed's thresholds),
`degraded` (live capacity below configured), `struck` (an incident window
is open on it at `position`, from `activeIncidents(chaos, position)`; a
window that names no node strikes every node). `struck` follows the clock,
not the tick, so the node is marked the moment the incident begins.
`edgeRates[i]` is requests per second on `edges[i]`; `pulseLevel(rate, maxEdgeRate(ticks, interval))`
is 0–4. `visibleLines(lines, position)`; `feedTime(62)` → `t=62s`.

### `LiveStage` (owns the clock)
Props: `nodes`, `edges`, the `feed` from context, and everything the
Topology panel passes to the diagram today. Inside:
- `playback` state; a `requestAnimationFrame` loop calls
  `setPlayback((p) => advance(p, dt, liveEdge(feed.ticks), complete))` while
  `playing` (`complete` = the feed's phase is `measured`, `done` or `failed`).
  Cancel the loop on unmount and when paused.
- A new run (`feed.started.run_id` changes) → `startPlayback(started.duration)`.
- `index = frameIndex(feed.ticks, playback.position)`; the frame is
  `useMemo`'d on `[index, incident state, feed.ticks, feed.chaos]`, so the
  memo'd `TopologyDiagram` redraws per tick, not per animation frame.
- Layout: diagram and feed side by side at `xl` (feed ~320px, same height as
  the diagram, scrolls inside itself), stacked below; `PlaybackBar` under them.
- The wrapper keeps the class `eleven-live` and stays a **direct child** of
  `.eleven-results` (that is what keeps it undimmed during a run).
- No feed yet (no run, or a result without ticks) → the diagram exactly as today.

### `TopologyDiagram` with a `live` frame
New optional prop `live?: LiveFrame | null` (and `maxEdgeRate`). Absent or
`null`: unchanged. Present:
- the node's utilization bar and percentage show `live.nodes[i].utilization`
  in `tone`'s colour; the queue shows when > 0;
- a `degraded` node shows `capacity/configured` slots (e.g. `2/4`) in the crit colour;
- a `struck` node gets the flash ring (one-shot when it becomes struck, then a steady crit ring while it lasts);
- each edge carries `pulseLevel` dots moving source → target (CSS animation
  along the edge path, e.g. `offset-path`, staggered by `animation-delay`);
  an edge with level 0 carries none;
- pulses pause when playback is paused (`animation-play-state`).
Extend the view model in `topologyView.ts` with these primitives (a new
function next to `nodeViews`; `nodeViews` itself keeps its output, its test is locked).
The run-level sizing label and the inspector (`onOpen`) keep working during playback.

### `EventFeed`
`visibleLines(feed.lines, position)`, newest at the bottom, auto-scrolled to
the bottom unless the user scrolled up. One row per line: `feedTime(line.t)`
in mono, a severity dot (`info` → the ok colour, as `FindingCard` maps it),
then `line.text` **verbatim**. `role="log"`, `aria-live="polite"`. Empty:
`Nothing to report yet.` A clean, healthy run may never print a line; that is correct.

### `PlaybackBar` (the scrubber comes in 3.4)
Play/pause button, the speed as a segmented control (`1× 2× 5× 10× 20×`),
`t=62s / 120s` in mono, and a badge: `LIVE` while the run is still arriving
and the clock is at the live edge, `REPLAY` otherwise.

### Reduced motion
`usePrefersReducedMotion()`: no pulses, no flash animation (a steady ring
instead), bars change without transition. The clock, the feed and the
numbers work the same.

## Result

### What changed
- `web/src/core/lib/playback.ts`, `liveView.ts` — new, to the contracts. `frameIndex` is a binary search (it runs every frame). `liveView.ts` also holds `withLive` (see the deviation below).
- `web/src/core/lib/topologyView.ts` — `TopologyDiagramProps` gains `live`, `maxEdgeRate`, `paused`, `reducedMotion`; `NodeViewModel` gains optional flat `live*` fields. `nodeViews` is unchanged.
- `web/src/core/components/TopologyDiagram.tsx` — with a `live` frame: bar and % are the moment's load in `liveTone`'s colour (the card's tint and word stay the run's verdict); `q5` and `1/3` on the name row for queue and lost slots; a critical ring (`eleven-strike`, flashes on appearance) while an incident is on the node; edges carry 0–4 dots with SVG `animateMotion` (evenly staggered with negative `begin`); `svg.pauseAnimations()` while paused; no dots under reduced motion; the legend gains "incident in progress" and "bar = load at t=Ns, dots = requests moving".
- `web/src/core/components/LiveStage.tsx`, `EventFeed.tsx`, `PlaybackBar.tsx` — new. `LiveStage` owns the clock (rAF, frames capped at 250 ms after a hidden tab); the frame is memoised on the newest tick or incident mark at or before the clock, so the diagram redraws per tick. A finished run returns the diagram to the run summary. A run this tab has not played starts from 0; coming back to the page shows it at its end.
- `web/src/app/page.tsx` — `LiveStage` in the Topology panel, inside `.eleven-live`, still a direct child of `.eleven-results`.
- `web/src/app/globals.css` — `eleven-strike`, `eleven-live-bar`, both still under reduced motion.
- `docs/AGENTS.md` — components, lib, layout paragraph.

### Deviations from the card
- **`withLive` lives in `liveView.ts`, not `topologyView.ts`.** The locked `topologyView.test.ts` pins `nodeViews` as that module's only runtime export; the card contradicted it, and the test wins.
- **The feed sits under the diagram below `2xl`, not beside it at `xl`.** Measured at 1440 px: the 5-node demo diagram needs ~1080 px and never shrinks, so with a 300 px feed beside it the db node was cut off.
- **The queue is on the name row** (`q5 1/3`), not beside the %: `UNDERSIZED q6 100%` overlapped on a 160 px card.

### Verify
- `vitest run --exclude replay/clickToFail/trafficShape`: 21 files, 256 tests passed. `tsc`: errors only in those three files. `eslint`: clean.
- By eye (headless Chrome, demo under `db_failover`, motion forced to `no-preference`, because headless Chrome reports reduced motion by default): the run plays t=0 → 58 s in ~11.8 s at 5×; 5–7 pulses on the edges; at t=15 s the db gets the critical ring and `0/3`, then `1/3` at t=20 s, bar red at 100% with `q5`; pricing_api amber at 75%; at the end the diagram returns to the run summary. - The badge reads `REPLAY` on every demo run: the whole run arrives before the first frame (0.1 s), so the clock is never at the live edge of a run still arriving. `LIVE` appears only on runs slow enough to stream in real time.
