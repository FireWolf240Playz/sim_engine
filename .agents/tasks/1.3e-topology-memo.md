# Task 1.3e — the topology redraws only the nodes that changed

> Written by Claude, executed by Qwen. First of three render cards
> (1.3e → 1.3f → 1.3g). **Done and reviewed; see `## Review` at the end.**
> The design below is historical: 1.3f supersedes its comparators.

## Goal
Downsizing one node, a re-run that returns the same numbers, the Run
button's pending flip, or pointing at a node re-renders only the node
cards whose picture actually changed, instead of the whole diagram.

## Why it redraws everything today (the investigation)
1. `HomePage` reads the whole run context, so every context change
   re-renders it, and `TopologyDiagram` is not `memo`. An Apply & re-run
   causes at least three full redraws: config patched + pending on, then
   result in + pending off, plus the fix-log updates.
2. `TopologyDiagram` re-runs `layout()` and `computeEdges()` on every
   render, and `layout()` returns new `Positioned` objects each time.
3. `NodeView` is not `memo`. Its props are objects that are new on every
   render or response: `p` comes from (2), `info` is a fresh
   `ComponentSizing` from each API response even when the numbers are
   equal, and `targetNames` is a new array from `playbookTargets` on
   every page render. Even with `memo`, nothing could be skipped.
4. Hover state (`active`) lives in the diagram, so each mouse enter or
   leave re-renders every node card and every edge.

`applySuggestions` already keeps untouched node objects identical; the
diagram just never takes advantage of it.

## The design (follow it; the tests pin its shape)
1. **`graphLayout.ts` — `layoutKey(nodes, edges): string`.** It changes
   exactly when `layout`/`computeEdges` could return something different:
   node names in order, plus the valid edges' `[source, target]` (reuse
   `validEdges`). Capacity, role, service time and probability are not
   in it. Build it with `JSON.stringify` so a `|` in a name cannot collide.
2. **New `web/src/core/lib/topologyView.ts`** (pure, no React):
   - `TopologyDiagramProps`: the diagram's props interface (move it here
     from the component).
   - `NodeViewModel`: everything one card draws, as primitives only:
     `name, role, capacity, status, meanUtil, p95Util, p95Queue,
     recommended` (`null` when there is no sizing yet), `isTarget`,
     `inPath`. No hover state in it.
   - `nodeViews(nodes, sizing, targetNames, wholePath): NodeViewModel[]`,
     in node order.
   - `sameNodeView(a, b)`: value equality over every field.
   - `changedNodes(prev, next): string[]`: names in `next` that are new or
     differ, then names that exist only in `prev`.
   - `NodeBodyProps = { view: NodeViewModel; x: number; y: number }` and
     `nodeBodyPropsEqual(a, b)`: same x, same y, `sameNodeView`.
   - `topologyPropsEqual(a, b)`: same `layoutKey`, the same edges in order
     (source, target, probability), and every node view `sameNodeView`.
3. **`TopologyDiagram.tsx`:**
   - Geometry: `const key = layoutKey(nodes, edges)` and
     `useMemo(() => …, [key])` for the positions, canvas size and edge
     geometry. Cache **positions by name** (`x, y, col`), never the node
     objects: a cached `Positioned.node` would show the old capacity after
     a downsize. The narrower dependency is correct because the key covers
     every input the layout reads. Write one
     `// eslint-disable-next-line react-hooks/exhaustive-deps` with that
     reason, and nothing broader.
   - Split `NodeView` in two:
     - `NodeShell` (plain function): the focusable `<g role="group">`
       with `tabIndex`, `aria-label`, `opacity` (dimmed), the four
       handlers, then `<NodeBody>`, then, only when `isActive`, an overlay
       `<rect>` (same box, `rx=10`, `fill="none"`, accent stroke 1.6) for
       the emphasis that today changes the card's own stroke.
     - `export const NodeBody = memo(function NodeBody(props: NodeBodyProps)
       {…}, nodeBodyPropsEqual)`: halos and ring, card rect, chip, glyph,
       name, status word, utilization text and bar, and the `<title>`. It
       reads only `view`, `x` and `y`.
   - `export const EdgeView = memo(function EdgeView(...))` with primitive
     props only (`d`, `title`, `long`, `lit`, `emphasized`). The default
     shallow compare is enough.
   - `export const TopologyDiagram = memo(function TopologyDiagram(props:
     TopologyDiagramProps) {…}, topologyPropsEqual)`.
   - Pass `setActive` straight through as `onActivate` (it is stable).
   - Use named functions inside `memo(...)` so `react/display-name` stays
     quiet.

## Review (Claude, 2026-10-09): kept; the comparators are superseded by 1.3f

The attempt matched this card and was green (123 of 123 in its scope). The
snapshot is on `qwen/1.3e-attempt-1`. The fault was in this card's design,
not in the execution: measured afterwards, a full diagram render costs
0.41 ms (5 nodes) to 4.2 ms (60 nodes), and the by-value comparators add
silent-staleness risk for no visible gain. **Kept:** `layoutKey`, the
geometry cache by name, `NodeShell`/`NodeBody`, the active overlay,
`EdgeView`. **Removed in 1.3f:** `sameNodeView`, `changedNodes`,
`nodeBodyPropsEqual`, `topologyPropsEqual`, replaced by structural sharing
(`shareResult`) and flat props under plain `memo`. The tests in
`web/tests/topologyView.test.ts` were rewritten to match. No `## Result` is needed for this card.
