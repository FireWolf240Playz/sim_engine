# Task 1.3f — simplify 1.3e: fix data identity at the source, drop the comparators

> Written by Claude, executed by Qwen. Your 1.3e work is **kept**: the
> `NodeShell` / `NodeBody` split, the active overlay, `EdgeView`, `layoutKey`
> and the geometry cache all stay. The snapshot is on `qwen/1.3e-attempt-1`.
> This card removes the part of my 1.3e design that turned out to be wrong.

## Goal
Plain `memo` with no hand-written comparators skips every card and panel
whose data did not change, because unchanged data keeps its identity.

## Evidence (measured 2026-10-09, node, original diagram)
| | 5 nodes | 60 nodes |
|---|---|---|
| full diagram render | 0.41 ms | 4.2 ms |
| `topologyPropsEqual` | 0.003 ms | 0.025 ms |

Hover at 60 nodes costs a frame on a phone, so the `NodeBody` memo is worth
keeping. The comparators are not: they rebuild every view twice per page
render, and a field missing from `VIEW_FIELDS` would freeze a card silently
(1.3g adds `remeasure`, which is exactly that risk).
`replaceEqualDeep` from `@tanstack/react-query` (already a dependency)
keeps unchanged parts of a new result identical (tested), so the default
compare is enough.

## Steps
1. **New `web/src/core/lib/runResult.ts`:**
   `export function shareResult(prev: SimulateResponse | null, next: SimulateResponse): SimulateResponse`,
   which returns `next` when `prev` is null and `replaceEqualDeep(prev, next)` otherwise.
2. **`RunStateContext.tsx`:** in `onSuccess`, replace
   `setResult(outcome.data)` with `setResult((prev) => shareResult(prev, outcome.data))`.
   Change nothing else; the token guard stays exactly as it is.
3. **`topologyView.ts`:** delete `VIEW_FIELDS`, `sameNodeView`, `changedNodes`,
   `NodeBodyProps`, `nodeBodyPropsEqual`, `topologyPropsEqual`. The only runtime
   export left is `nodeViews`. Keep `TopologyDiagramProps`,
   `NodeViewModel` and `nodeViews` unchanged.
4. **`TopologyDiagram.tsx`:**
   - Import only `nodeViews`, `NodeViewModel` and `TopologyDiagramProps`. Declare
     locally `type NodeBodyProps = NodeViewModel & { x: number; y: number };`
   - `NodeShell` renders `<NodeBody {...view} x={x} y={y} />`. The props are flat,
     so the default compare sees primitives.
   - `NodeBody = memo(function NodeBody({ x, y, ...view }: NodeBodyProps) {…})`,
     with no second argument. The body code is unchanged.
   - `TopologyDiagram = memo(function TopologyDiagram(…) {…})`, with no second argument.
   - `EdgeView` loses its `memo`: `export function EdgeView(...)`, body unchanged.
     An edge is one `<path>`; no measurement justifies memoizing it.
   - Update the two doc comments that mention the comparators.
5. **`page.tsx`:**
   - Add `const NO_EDGES: TopologyEdge[] = [];` at module level and pass
     `edges={config.topology.edges ?? NO_EDGES}`.
   - Wrap the `playbookTargets(...)` call in
     `useMemo(() => playbookTargets(playbook, config.topology.nodes), [playbook, config.topology.nodes])`.
6. **New `web/src/core/lib/verdictView.ts`:** `export function findingKeys(rows: Finding[]): string[]`.
   The key is `JSON.stringify([id, node ?? null])`, and a repeat of the same pair gets a
   `#2`, `#3`… suffix in order.
7. **`VerdictPanel.tsx`** and **`VerdictReportModal.tsx`** (line 146): render
   `findingKeys(rows).map((key, i) => <FindingCard key={key} finding={rows[i]} />)`.
   Both currently use `${row.id}-${index}`.
