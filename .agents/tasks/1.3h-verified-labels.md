# Task 1.3h — the sizing label is the verified answer

> Written by Claude, executed by Qwen. Scope chosen by the user: **label
> only**. The score, the cost grade and the `undersized` finding do not change.

## Goal
Every sizing word and size on screen (sizing table, topology cards, compare
page, CLI) says what "Fix it" will do to that node, so the two can never
disagree. Mean utilization stays on screen as the evidence.

## Evidence (measured 2026-10-10, demo, clean run + 4 incidents)
- **9 of 25 node labels disagree with the verified fix.** Under every incident
  the db reads `right_sized` while Fix it raises it (3→6, 3→8 under
  cache_eviction_storm); `pricing_api` likewise under 3 incidents; the worker
  reads `oversized` (29–45% mean) in 3 incidents where no cut is safe.
- On the clean run the "Rec. capacity" column shows the formula's worker ×4,
  which breaches the SLA; the verified cut is ×5.
- The verified plan already runs on every request (92–220 ms), so this card
  adds **no** simulation runs.

## Why the old `status` stays
`status` (mean-utilization thresholds in `metrics.py`) is read by the score
(`score.py` sizing term and cost grade), by the `undersized` finding, and by
the right-sizer's own search (`rightsize.py::_cut_is_free`, `_raise_clears`).
Replacing it would change every documented score and make the search
circular. So the answer goes in two **new** fields beside it.

## Steps
1. **`sim_core/rightsize.py`:** append
   `def verified_sizing(config: SimulationConfig, suggestions: list[Suggestion]) -> dict[str, tuple[str, int]]`.
   For each node in `config.topology.nodes` order: `after` = the suggestion's
   `proposed` for that node, else `max_capacity`; status `"oversized"` if
   `after < max_capacity`, `"undersized"` if greater, else `"right_sized"`;
   value `(status, after)`. Pure; docstring says it never disagrees with Fix it.
2. **`sim_core/engine.py` `run()`:** in the `if suggest:` block, after
   `summary["fix_outcome"] = …`, write `verified_status` and
   `verified_capacity` into each existing `summary["component_sizing"][name]`
   from `verified_sizing(self.config, plan["suggestions"])`. Import it next to
   `plan_fix`; put the `# local: …` comment on its own line above the import
   (one line would exceed 100 chars). With `suggest=False` nothing is added.
3. **`sim_core/compare.py` `diff_runs`:** the sizing map reads
   `info.get("verified_status", info.get("status"))`.
4. **`sim_core/cli/sim.py` `_format_summary`:** heading
   `"Right-sizing check (verified by simulation)"`; each line prints
   `info.get("verified_status", info["status"])` and
   `size-to {info.get("verified_capacity", info["recommended_capacity"])}`.
5. **`web/src/core/types.ts` `ComponentSizing`** (authorized by this card):
   add optional `verified_status?: SizingStatus` and `verified_capacity?: number`,
   with a doc comment saying they are absent on `suggest=False` runs.
6. **`web/src/core/lib/format.ts`:** `export function sizingLabel(info: ComponentSizing): { status: SizingStatus; capacity: number }`
   returning `verified_status ?? status` and `verified_capacity ?? recommended_capacity`.
7. **`topologyView.ts` `nodeViews`:** `const label = info ? sizingLabel(info) : null;`
   then `status: label ? label.status : null` and `recommended: label ? label.capacity : null`.
   Utilization fields unchanged.
8. **`SizingTable.tsx`:** keep the 1.3g stale handling exactly as it is
   (`info` is `undefined` for a re-measured row; `web/tests/sizingTable.test.ts`
   pins it). Below the `info` line add `const label = info ? sizingLabel(info) : null;`;
   severity, the "Rec. capacity" cell and the verdict word come from `label`,
   and the stale `empty` / `remeasure` fallbacks stay. Doc comment: "Per-node
   right-sizing readout: the verified label, utilization as evidence."
