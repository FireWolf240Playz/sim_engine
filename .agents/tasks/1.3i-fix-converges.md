# Task 1.3i — Fix it converges in one apply, in single and 5-seed mode

> Written by Claude; built by Claude in the same session (the owner reported
> the bug in the browser and asked for it fixed).

## Goal
After "Apply & re-run", the re-run scores exactly what the Fix-it preview
predicted and has nothing left to change: in 5-seed mode, under every
incident, under every traffic shape.

## What was measured (demo, seed 42, 2026-11-15)
- **5-seed mode never settled.** Each seed planned on its own; the page
  showed the typical seed's plan. The re-run's typical seed moved
  (44 → 46 → 44 → 45 → 42 → 44 under cross_region_latency_spike), so no
  prediction held, and successive plans undid each other: db 3 → 4 → 3,
  lb 10 → 5 → 4 → 3 → 4 → 3 over six applies. The worst seed stayed at 75–85.
- **A capacity-fixable breach was called unfixable.** db_failover + ramp
  stopped at 66.5 with "sla_breach — capacity can't fix it". Every single
  raise (pricing_api 4 → 8: 66.5 → 71.7) also brought a `p95_headroom`
  warning, and `_helps` refused any raise that added a warning. worker 12,
  pricing_api 8, db 12 together score 98.6 with no finding. In 5-seed mode
  the plan only trimmed, and the worst seed fell from 60.6 to 42.0.
- **One apply was not the end state under diurnal traffic.** Cuts made after
  the raises opened room for another raise; the re-run offered a second plan
  (cache_eviction_storm: 15.7 → 90.4, then → 97.1).

## Design (prototyped in a scratch script before the card)
1. `_helps`: fewer crit always helps, more crit never; at equal crit, fewer
   warn helps, and so does a gain of `MIN_REPAIR_GAIN` points even with a
   warning more.
2. Rounds: repair → undersized/trim passes, repeated while findings remain
   and the passes changed something (`MAX_ROUNDS` 4). The plan ends where a
   re-plan changes nothing.
3. `plan_fix_seeds(config, seeds, summaries)`: one plan for a multi-seed run.
   Every candidate is simulated on every seed and merged (`_merge`): the
   typical run's score (what the re-run headlines), every seed's findings
   tagged with their run, a node undersized if it is on any seed, waits
   added, peaks and mean utilisation maxed. A cut is free only if no seed
   gains a finding. `FixOutcome.seeds` lists the seeds; reasons say
   "verified by simulation, seeds 42–46".
4. `engine.attach_fix_plan_seeds` attaches that one plan to every seed's
   summary; `/simulate`, `/runs` and `run --seeds` use it.
5. Web: `FixOutcome.seeds?` in `types.ts`; `fixHistory.ts::measuredOn`;
   the preview says "on seeds 42–46, the same runs the re-run will show".

Prototype result, 5 seeds, one apply each: cross-region flat 89.7 → 97.6,
cross-region ramp 57.4 → 97.1, db failover ramp 64.0 → 97.4, db failover
diurnal 60.1 → 97.4 — every re-run equal to its prediction, every next plan
empty. Single seed: 14 of 16 incident × shape pairs settled in one apply
with fix 1, all 16 with fixes 1 + 2.

## Result
- Built as designed, with one correction found by timing: the first build
  looped rounds while the trim passes "changed something". On the 20-node
  example the passes hit `MAX_PASSES` without settling, so rounds kept
  trimming (70.4 → 70.3 → 69.5) and the plan took 85 s instead of 40 s.
  Rounds now continue only while *repair* changes something.
- Cost, measured against HEAD's planner (`git show HEAD:sim_core/rightsize.py`):
  single seed — production_platform 7.2 s (HEAD 6.6), with db_failover
  15.4 s (14.4); microservice_platform 44.2 s (43.5), with db_failover
  29.6 s (27.9). Five seeds — one shared plan vs HEAD's five per-seed plans:
  api_stack 2.8 s (3.7), checkout_stack 2.4 s (2.7), production_platform
  88.9 s (64.0), microservice_platform 132.8 s (149.7). The 15-node case is
  dearer because every cut must be free on all five seeds; HEAD's cheaper
  plans did not hold after an apply. `tests/test_fix_converges.py` 27/27; engine suite 610
  passed (583 + 27), exit 0; web 318/318 (314 + 4), typecheck and lint clean;
  ruff on the changed files adds no finding (57 before, 57 after).
- **Re-pinned a locked contract, openly:**
  `tests/test_profile.py::test_api_multi_run_matches_individual_runs` (1.1)
  required each seed of a multi-seed run to equal that seed run alone, plan
  included. The measurement still is equal; the plan is not, by design (one
  plan verified on every seed). The test now compares the summary without
  the plan's keys (`suggestions`, `fix_outcome`, `cost_grade`, the verified
  sizing labels) and checks the outcome names all three seeds.
