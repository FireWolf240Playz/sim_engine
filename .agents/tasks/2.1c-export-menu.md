# Task 2.1c — export center: the download menu in the web UI

> Written by Claude, executed by Qwen. Roadmap 2.1, third of three cards.
> **Start only after 2.1 and 2.1b are merged**: this card calls `POST /export`
> and `GET /export/formats`. Pure frontend; no engine or API change.

## Goal
A finished run shows an "Export" panel with one button per format; a click
downloads the file of exactly the run on screen.

## Evidence (checked 2026-11-14)
- The API keeps no run. `POST /export {config, playbook, format}` simulates
  the config again and returns the file with
  `Content-Disposition: attachment; filename="eleven-<playbook|run>-seed<seed>.<ext>"`.
  A config without a seed is a 422; a run over the work budget is a 422 with a
  sentence in `detail`.
- So the request must name the run **on screen**, and three things drift from it:
  1. the incident picker changes `playbook` without running;
  2. "Apply & re-run" changes `config` before the re-run is measured;
  3. in the 5-seed mode the headline is the run of `result.typical_seed`, not
     of `config.seed`.
  `RunStateContext` already keeps the config a result was measured with
  (`measuredConfig`) but not its playbook, and exposes only `measuredNodes`.
- `request<T>()` in `client.ts` reads every response as text and parses JSON;
  a workbook is binary, so a download needs its own path.
- Export time on the demo is 0.1 s; on the 19-node examples the Excel and
  JSON formats take 5-13 s (they include the Fix-it plan). Use the `heavy`
  timeout.
- **Not prototyped in a browser.** The lib and client contracts below are
  pinned by tests; the panel's look is checked by eye at review.

## Steps
1. **`web/src/core/types.ts`:** already has `ExportFormatName`, `ExportTier`,
   `ExportFormatInfo`, `ExportFormatsResponse`, `MeasuredRun`, `ExportRequest`.
   Do not edit it.
2. **New `web/src/core/lib/exports.ts`** (pure, no React, no DOM):
   - `exportRequest(run: MeasuredRun, result: Pick<SimulateResponse, "typical_seed">, format: ExportFormatName): ExportRequest`
     → `{ config: { ...run.config, seed: result.typical_seed ?? run.config.seed }, playbook: run.playbook, format }`.
   - `exportFilename(request: ExportRequest, extension: string): string`
     → `` `eleven-${request.playbook ?? "run"}-seed${request.config.seed}.${extension}` ``.
   - `filenameFromDisposition(header: string | null): string | null` — the
     `filename=` value, quoted or not; only the part after the last `/` or
     `\`; `null` when absent or empty.
   - `interface ExportChoice { name: ExportFormatName; label: string; extension: string; badge: string | null; available: boolean }`
   - `exportChoices(formats: ExportFormatInfo[]): ExportChoice[]` — same order;
     `badge` is `"Pro"` for `tier === "paid"`, else `null`; `available` is
     always `true` (the API gates, once it knows the user).
3. **`web/src/core/api/client.ts`:**
   - `api.exportFormats = () => request<ExportFormatsResponse>("/export/formats")`.
   - `api.exportRun(body: ExportRequest): Promise<{ blob: Blob; filename: string }>`:
     its own `fetch` (POST, JSON body, same headers, `cache: "no-store"`,
     `AbortSignal.timeout(TIMEOUT_MS.heavy)`), the same unreachable / timeout
     handling as `request`. Not ok → read the body as text and throw the same
     `ApiError` `request` would (factor that error-building out of `request`
     into one helper both use; do not copy it). Ok → `blob = await response.blob()`,
     `filename = filenameFromDisposition(response.headers.get("Content-Disposition")) ?? exportFilename(body, body.format)`.
4. **`web/src/core/state/RunStateContext.tsx`:** add `playbook` to the
   `RunOutcome` success variant (the `pb` the run was started with); keep it in
   a `measuredPlaybook` state set beside `setMeasuredConfig` and cleared where
   that is cleared. Expose `measuredRun: MeasuredRun | null` on the context
   value (`measuredConfig ? { config: measuredConfig, playbook: measuredPlaybook } : null`),
   memoised so its identity changes only when either part does.
   `measuredNodes` stays.
5. **New `web/src/core/components/ExportMenu.tsx`** (`"use client"`), props
   `{ run: MeasuredRun; result: SimulateResponse; disabled: boolean }`:
   - `useQuery({ queryKey: ["export-formats"], queryFn: api.exportFormats, staleTime: Infinity })`.
   - One `<button type="button">` per `exportChoices(...)` entry, same classes
     as `FixDiffPanel`'s secondary "Copy YAML" button; the label, then the
     badge as a small `text-[10.5px] uppercase` chip when not null.
   - Click → `api.exportRun(exportRequest(run, result, name))`, then save:
     `URL.createObjectURL(blob)`, a temporary `<a download={filename}>`,
     `click()`, `URL.revokeObjectURL`. While one is in flight that button
     reads "Preparing…" and all are disabled.
   - A failure renders one line under the buttons with `role="alert"`:
     the `ApiError` message when it is one, else "The export failed — try again."
   - Under the buttons, one dim line: "The file is this exact run, simulated
     again from its seed."
6. **`web/src/app/page.tsx`:** read `measuredRun` from `useRunState()`; after
   the "Fix it" panel add
   `{result && measuredRun ? <Panel title="Export" aside="the data behind this run"><ExportMenu run={measuredRun} result={result} disabled={isPending} /></Panel> : null}`.

- Send `config` from the page state: only `measuredRun` describes the result.
