# Task 1.3g — while a re-run is in flight, only what changed says so

> Written by Claude, executed by Qwen. Start only after 1.3f is approved.

## Goal
During Apply & re-run, the topology stays at full strength and only the
nodes whose size changed show they are being re-measured. The Fix-it panel
says what it is waiting for, and a failed re-run leaves those nodes marked
"not measured" instead of showing the old size's numbers as current.

## Evidence (what you see today)
- `.eleven-results[aria-busy]` fades the **whole** results block to 55%, so one
  downsize visibly dims the entire diagram. This is the main thing users notice.
- The config patches immediately while `sizing` still belongs to the old size,
  so the changed node shows the new ×N next to the old utilization.
- **Bug:** right after Apply, the Fix-it panel reads *"Nothing to change: every
  node is the right size for this load"* while the re-run is still running, and
  it keeps saying so if the re-run fails.

## Steps
1. **New `web/src/core/lib/rerun.ts`:**
   - `staleNodes(measured: TopologyNode[] | null, current: TopologyNode[]): string[]`:
     names in `current`, in order, whose `max_capacity` differs from the
     measured run's, or that the measured run did not have. `[]` when `measured` is null.
   - `fixPanelView({ pending, suggestions, hasOutcome, isPending })` →
     `{ diff, outcome, note }`, with `note` one of `"rerunning" | "applied" | "nothing" | null`:
     - `pending > 0` → `{ diff: true, outcome: hasOutcome, note: null }`
     - `pending === 0 && suggestions > 0` → `{ diff: false, outcome: false, note: isPending ? "rerunning" : "applied" }`
     - `suggestions === 0` → `{ diff: false, outcome: hasOutcome, note: hasOutcome ? null : "nothing" }`
2. **`topologyView.ts`:** add `remeasure: "running" | "unmeasured" | null` to
   `NodeViewModel`, and a fifth `nodeViews` parameter
   `stale: { names: readonly string[]; running: boolean } = { names: [], running: false }`.
   Add optional `stale` to `TopologyDiagramProps` and pass it to `nodeViews`. Props
   are flat (1.3f), so the new field reaches `NodeBody` with no comparator to update.
3. **`RunStateContext.tsx`:** expose `measuredNodes: TopologyNode[] | null`, the
   nodes of the config the current `result` was simulated with. Add the effective
   config to the success `RunOutcome` and set it beside `setResult`. On failure,
   keep the old value. Reset it to `null` in `setArchitecture` / `resetArchitecture`.
   **The token guard does not change.**
4. **`page.tsx`:**
   - `const staleNames = useMemo(() => staleNodes(measuredNodes, config.topology.nodes), [measuredNodes, config.topology.nodes])`,
     then `const stale = useMemo(() => ({ names: staleNames, running: isPending }), [staleNames, isPending])`,
     passed as `stale={stale}`.
   - Render the Fix-it panel from `fixPanelView(...)`. Note copy: `rerunning` →
     "Re-running with your change…"; `applied` → "Applied, not yet measured: run
     again to see the result."; `nothing` → keep today's sentence.
   - Wrap the Topology `<Panel>` in `<div className="eleven-live">`.
5. **`globals.css`:** a parent's opacity cannot be undone by a child, so change the
   rule to dim the **children** of `.eleven-results[aria-busy="true"]` except
   `.eleven-live`, and move the transition onto the children.
6. **`TopologyDiagram.tsx` (`NodeBody`):** when `remeasure` is set, draw the card
   stroke dashed, set the status word to `MEASURING…` or `NOT MEASURED`, set the
   utilization text to `—`, and draw no utilization fill (the track stays). Use
   existing tokens only (`stroke-accent`, `fill-ink-dim`), and nothing animates
   under reduced motion.
